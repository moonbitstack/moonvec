pub struct Buffer { data : FixedArray[Byte] dtype : DType len : Int32 }

A flat block of elements of one dtype, which views of an array share. The bytes are little endian on every target, so a buffer written on one machine reads back the same on another and a file of vectors can carry raw values. Storage is a byte array rather than a typed one because one code path has to hold every dtype; the accessors below are the only place that knows the widths.

pub struct NDArray { buffer : Buffer shape : Array[Int32] strides : Array[Int32] offset : Int32 }

An N-dimensional array: a view over a flat buffer, described by a shape and a stride per axis. The strides are counted in elements, not bytes, and follow C order: the last axis varies fastest. Any axis may have stride 0, which is how a size-one axis broadcasts without copying its data, and any axis may be negative, which is how a reversed view is made. Two arrays made by slicing the same array share one buffer, so a write through one is visible through the other.

pub(all) enum Number { Boolean(Bool) Signed(Int64) Unsigned(UInt64) Real(Double) Complex(Complex) }

One element of an array, widened to the type that holds its whole range. The variants name the class the value belongs to rather than one variant per dtype: reading an int16 gives Signed too, and writing it back checks the width. This keeps a kernel written once per operation instead of once per dtype.

pub struct Plan { outer_sizes : Array[Int32] outer_strides : Array[Array[Int32]] run : Int32 run_strides : Array[Int32] operands : Int32 starts : Array[Int32] }

A loop schedule over a shape: the axes that vary between runs, and the length of the innermost run that stays contiguous for every operand. Adjacent axes are merged when every operand walks them at a constant step, which turns a contiguous pair of arrays into a single tight loop instead of one call per element. Each run hands the loop body the buffer offsets of all operands at the start of the run.

pub fn broadcast_shape(Array[Int32], Array[Int32]) -> Array[Int32] raise VecError

The shape two arrays take when an elementwise operation meets them. The axes are aligned from the right; an axis missing on one side counts as 1, and an axis of 1 stretches to the other side's length. What an array operation refuses to do. Shapes and axes are checked before any element is touched, so an error never leaves an array half written. Arithmetic that has no answer — an integer divided by zero, an overflowing cast — also lands here rather than returning a number that looks valid.

pub(open) trait Kernel { fn name(Self) -> String fn binary(Self, BinaryOp, DType, Buffer, Int32, Int32, Buffer, Int32, Int32, Buffer, Int32, Int32, Int32) -> Unit raise VecError fn unary(Self, UnaryOp, DType, Buffer, Int32, Int32, Buffer, Int32, Int32, Int32) -> Unit raise VecError fn matmul(Self, DType, Buffer, Int32, Buffer, Int32, Buffer, Int32, Int32, Int32, Int32) -> Unit raise VecError fn reduce(Self, ReduceOp, DType, Buffer, Int32, Int32, Int32, Number) -> Number raise VecError }

What an array backend has to provide: the arithmetic over runs of contiguous elements. Everything else — broadcasting, striding, dtype promotion, allocation — belongs to the array layer above, so a backend only has to be fast on long flat runs and never sees a shape. A run is always within one buffer and one dtype, and the offsets are in elements. Implement this trait to add a backend: a C stub, a compute shader, a vector unit. The array layer takes it as a parameter and does not change.

A layout is a length and a stride, or a tuple of layouts. It holds no data; it names an offset that an array view can be built on, which is what a tiled kernel needs.

Types

pub(all) enum Layout { Mode(Int32, Int32) Tuple(Array[Layout]) }

A tensor layout: the mapping from a coordinate to an offset in a flat buffer. A layout is either a single mode — a length and the distance between neighbours — or a tuple of layouts, which lets a tile of a tile of a matrix stay one object instead of being flattened into a shape nobody can read back. Nothing here holds data: a layout is the description of where the elements of a tensor sit, which is what a kernel needs and what a view is built from. A stride may be 0, which repeats an element along that axis (how a broadcast is expressed without copying), or negative, which walks an axis backwards.

pub fn Layout::coalesce(Self) -> Self

Merges adjacent modes that walk the buffer at a constant step, so that a layout with one row per thread becomes one mode instead of many. Two modes merge when the outer one's stride equals the inner one's stride times the inner one's size: then the pair is a single run. A size-one mode disappears, and a stride-zero mode is kept apart because it repeats rather than advances.

pub fn Layout::cosize(Self) -> Int32

One past the largest offset the layout can produce, which is how much space a buffer of this layout needs.

pub fn Layout::divide(Self, tile~ : Int32) -> (Self, Self) raise LayoutError

Splits the leading mode into a tile of tile elements and the rest. This is the operation a kernel uses to give each thread a block: the tile part addresses the elements within one block, the rest picks the block. The two multiply back to the original size.
